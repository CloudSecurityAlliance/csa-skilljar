# ADR-007: Phase order set by usage evidence, not API size

**Date:** 2026-08-26
**Status:** Active
**Decision method:** Collaborative — AI probed the reference org; evidence reversed two prior recommendations

## Goal

Order the v1-only families, and decide which to cut.

## Context

The v1-only surface is roughly 250 operations across eight candidate families. The initial ordering
was reasoned from the API's own structure, which put commerce last on the grounds that agents have
little business creating promo codes.

A read-only probe of CSA's production org replaced that reasoning with counts:

| Family | Rows | Family | Rows |
|---|---|---|---|
| users | 42,669 | web-packages | 533 |
| promo-codes | 13,687 | offers | 376 |
| promo-code-pools | 4,278 | vilt-registrations | 341 |
| assets | 157 | labels | 50 |
| published-paths | 10 | webhooks | 3 |

Four families returned **zero rows**: license-packages, progresstokens, ilt-multi-session-events,
access-code-pools.

## Decision

Order: **learner progress → assets and media → commerce (read-biased) → learning paths → events
and webhooks → ILT/vILT → labels and tags.**

Cut outright: catalog page-building, license packages, progress tokens, multi-session events,
access-code pools.

## Rationale

- **Progress first** despite modest row counts: it is the largest functional gap in v2 and
  reporting is what people most often ask an agent for.
- **Commerce moved from last to third.** 13,687 promo codes and 4,278 pools make it the most
  populated subsystem in the org. The volume argues for *read* tools — which pool does this code
  belong to, was it redeemed — not bulk creation, so the family ships read-biased.
- **Four families cut on evidence**, not taste. Building tools for tables with no rows is
  speculative work that looks like completeness.
- **Catalog page-building cut on judgement**: ~60 operations for a page builder an agent should
  not drive.

## Rejected alternatives

- **Order by API size** — would put catalog and commerce first purely because v1 has many
  endpoints for them.
- **Order by v2 gap severity alone** — the original reasoning; produced a defensible order that
  the data contradicted in two places.
- **Build everything** — 250 operations of speculative surface, four families of it provably dead.

## Implementation

Not yet implemented. Phase table is design spec §4.4; probe results are Appendix A.

## Related decisions

The cuts are recorded as non-goals in design spec §2 so they read as decisions rather than
omissions.
