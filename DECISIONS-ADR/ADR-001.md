# ADR-001: Python, not TypeScript

**Date:** 2026-08-26
**Status:** Active
**Decision method:** AI proposal, human approved

## Goal

Pick the implementation language before any code exists, so the choice is deliberate rather than
inherited from whatever got typed first.

## Context

The user was open to either Python or TypeScript. CSA has one shipped MCP server,
[`csa-google-workspace`](https://github.com/CloudSecurityAlliance/csa-google-workspace) — Python,
stdio, read-write, on PyPI — and every `[proven]` MCP pattern in CINO-Platform-Engineering derives
from it: six Python SDK traps verified against `mcp` 2.1.0, the fail-closed `PolicyBackend`, the
demo-as-end-to-end-test, and the fake/real backend seam.

CSA's earlier MCP server (SecID-Service) is TypeScript, but it is a stateless Cloudflare Worker
over Streamable HTTP — a different shape in every dimension that matters here.

## Decision

Python, package `csa-skilljar`, import name `csa_skilljar`, `src/` layout, `mcp>=2.1`.

## Rationale

- Three of the six documented SDK traps **fail silently**. Choosing TypeScript discards that
  hard-won knowledge and guarantees rediscovering an equivalent set.
- The architectural patterns we intend to reuse are concrete Python code, not abstractions.
- CSA's content pipeline is Python, so the library half is usable by existing tooling.
- `pip install csa-skilljar` lands beside `csa-google-workspace` for the same operators.

## Rejected alternatives

- **TypeScript** — better fit if this were a remote Worker. It is not: credential locality argues
  for local stdio (ADR-003), which removes the main reason to prefer the Workers ecosystem.
- **Both** — a library in one, a server in the other. Doubles the surface for no benefit.

## Implementation

Not yet implemented. Lands with the Phase 1 scaffold.
