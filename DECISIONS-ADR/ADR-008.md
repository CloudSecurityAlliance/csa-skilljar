# ADR-008: Reject read-only fields that the official server silently ignores

**Date:** 2026-08-27
**Status:** Active
**Decision method:** AI proposal, human approved — surfaced while implementing Block 2 from the captured registry

## Goal

Decide what to do about fields the official Skilljar MCP server accepts on a write and
then discards without saying so.

## Context

The captured registry records two instances, both confirmed from the live tool
descriptions rather than the OpenAPI document:

- `update_lessons` — a lesson's `type` is read-only and *"absent from the schema; clients
  that send it have it **silently ignored** (not rejected)"*.
- `update_web_packages` — `type`, `state` and `base_path` are server-owned and *"a client
  that sends any of them has them silently ignored rather than rejected"*.

This sits directly against ADR-006, which promises identical tool and argument names to
the official server, with divergence only by *addition*.

## Decision

**Reject them, with a message that says the field is read-only and what to do instead.**
Recorded as a deliberate, enumerated exception to ADR-006 rather than a drift.

The rejection message also states that the official server accepts the field silently, so
a caller comparing the two implementations is not left guessing which is broken.

## Rationale

- ADR-006's promise is that *a caller sending exactly what the official server accepts
  gets exactly what it returns*. Silently discarding a field is not a **result** a caller
  can rely on — it is a defect, and reproducing a defect we can see is the thing that
  ADR-006's "additive compatibility" section already declined to do for `list_courses`'
  missing pagination.
- The failure mode is specifically bad for an agent: a model that sets `type` and reports
  success has told the user something false, and nothing anywhere will contradict it.
- The blast radius is small and enumerable — two tools, four fields — so this does not
  erode the parity promise generally.

## Rejected alternatives

- **Silent parity.** Faithful, and propagates a defect into the one project whose stated
  value is being better at the edges.
- **Warn and continue.** A warning in a tool result is read by nobody and by no model
  reliably; it produces the same false success with extra text.
- **Accept and echo back what was ignored.** Closer to honest, but it makes every write
  result carry a diagnostic channel that exists for two fields.

## Implementation

`src/csa_skilljar/mcp/_tools/lessons.py` — `_check_lesson_updates` rejects `type` with the
message above. Covered by
`tests/test_lessons_write.py::test_lesson_type_is_rejected_rather_than_silently_ignored`.
`update_web_packages` lands in Block 9 and must do the same for its three fields.
